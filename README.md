# Gost Home — контент-студия

Рабочая платформа контента: календарь съёмок, контент-план с долями участников, согласование, готовый запас и нормативы. Ролик (Reels или YouTube) хранится одной записью и открывается одинаково из любого раздела.

## Разделы

- Главная: опубликовано Reels и YouTube за месяц против плана, в производстве (нужно согласовать, на правках), готовый запас, срочные задачи, ближайшие съёмки и публикации.
- Календарь съёмок: прежний календарь без изменений поведения. В карточке съёмки видны её ролики и кнопка «＋ Ролик к этой съёмке». Съёмка не считается публикацией.
- Контент-план: список роликов месяца в стиле Notion (дата, название, ведущий, тип, этап), дату можно поменять прямо в строке; группа «Без даты»; фильтр Reels/YouTube; поиск. Сверху «Участники»: план, сколько снято и выложено в этом месяце и доли, считается автоматически по основному ведущему. «Снято» = этап «Снято» и дальше; дата съёмки берётся из привязанной съёмки, без неё из даты публикации. Сбоку карточка «Оплата съёмок» (только с правом выплат): «Осталось оплатить N рилс» и «Подробнее» с таблицей «снято / оплачено / осталось». «Снято» считается само и правится вручную, «Оплачено» ведётся вручную; хранится в app_settings[reel_pay_counts], читается и меняется только через /api/finance (право выплат, revision, audit). Там же свёрнуты прежние тарифы и выплаты в деньгах.
- Согласование: один список блоками по этапам: «Сценарий готов» → «Снято» (с пометкой «монтаж») → «Нужно согласовать» (с пометкой «правки») → «Согласовано» → «Выложено» (за выбранный месяц). Цикл версий и решений прежний: руководитель может только «Согласовать» и «На доработку».
- Контент-план → «Автоплан месяца»: предварительный просмотр Reels на оставшиеся дни месяца по нормативам (30 в месяц, Юля примерно каждые 3 дня, остальные равномерно, один участник не дважды в день). Уже назначенные и опубликованные ролики не двигаются, ролик из банка ставится один раз, нехватка роликов показывается пустыми слотами. Конфликты (например, Юля не помещается в ритм) показываются текстом. Сохраняются только отмеченные строки, одной транзакцией; если данные изменились, ничего не сохраняется.
- Задачник (только команде, сервер отвечает 403 остальным): простое планирование. Одна строка добавляет задачу и понимает срок словами: «завтра в 15:00», «в пятницу», «25.11», «3 декабря», «через 3 дня», «!» или «срочно» = важно; распознанное видно чипами, нажатие на чип оставляет слова в названии. Разделы: Просрочено, Сегодня, Завтра, На неделе, Позже, Без срока, Выполнено (свёрнуто). Круглая галочка закрывает задачу, перетаскивание в раздел меняет срок. Поля ответственного в интерфейсе нет (столбец в базе сохранён, старые значения не теряются). Задачу можно связать со съёмкой или роликом, архив вместо удаления.
- Отдельного раздела «Выплаты» в меню нет: всё в карточке «Оплата съёмок» контент-плана. Тарифы по участнику вводятся вручную, без тарифа начислений нет; начисления подтверждаются вручную, повторное начисление блокируется уникальным ключом; ошибки исправляются аннулированием с причиной, ничего не удаляется.
- Higgsfield AI: проекты вставок, привязанные к ролику; бриф, промпт изображения и движения; «Скопировать для ChatGPT»; материалы (заметки, ответы ChatGPT, референсы, ссылки на изображения и видео); утверждение кадра. Ручная работа доступна всегда. Запуск через официальный API только при ключах на сервере, после подтверждения, с уникальным ключом идемпотентности, в пределах месячного лимита (по умолчанию 0, то есть выключено). Видео (image-to-video) запускается только с утверждённого изображения. Стоимость API заранее не сообщает. Результаты сохраняются в закрытое хранилище проекта (если подключено), иначе ссылками провайдера с датой истечения.
- Настройки: нормативы месяца; интеграции с честным статусом «Не подключено» без ключей; Instagram: вход через Instagram (Business Login, scope instagram_business_basic), токен меняется на долгосрочный и хранится только на сервере в зашифрованном виде (AES-GCM), синхронизация публикаций и метрик (отсутствующие метрики остаются пустыми, не нулями), сопоставление публикации с согласованным роликом только по подтверждению пользователя; полная резервная копия JSON (без токенов) и восстановление с проверкой: добавляются только отсутствующие записи, существующие не меняются. Подходит и старая копия 7 съёмок.

Публикация отмечается вручную с фактической датой; запланированное никогда не считается опубликованным. Готовый запас = согласованные и ещё не опубликованные Reels. Покрытие считается по конкретным будущим датам: слот обеспечен, только если его собственный ролик согласован.

## Данные платформы

Миграция `drizzle/0002_platform_content.sql` только добавляет таблицы `content_items`, `content_participants`, `status_events`, `audit_events`, `app_settings`; таблица `shoots` и её записи не меняются. Откат: `db/rollback/0002_platform_content.down.sql` (удаляет только новые таблицы). Каждое создание, правка, смена статуса и сохранение нормативов выполняется одной транзакционной D1 batch (`lib/content-writes.ts`): изменение с проверкой версии, запись истории и журнала аудита применяются вместе или не применяются вовсе. При устаревшей версии ничего не пишется и возвращается 409.

Проверки: `node scripts/test-content-platform.mjs` (логика), `node scripts/test-atomic-writes.mjs` (атомарность на локальной D1 через Miniflare, включая откат при сбое записи истории), `node scripts/test-content-api.mjs` (API против локального сервера с локальной копией D1; на внешний адрес не запускается). Восстановление съёмок из резервной копии в локальную базу: `node scripts/legacy-shoots-to-sql.mjs <backup.json> <out.sql>`, затем `wrangler d1 execute DB --local --file <out.sql>`.

# Календарь съёмок

Приложение планирования контента для шести участников: Марк, Андрей, Александр, Юля, Лиза, Лада. Данные съёмок хранятся в облачной D1 базе при публикации через Sites. Сайт создаётся с закрытым доступом владельца.

## Работа

- Добавляйте съёмку кнопкой вверху или плюсом в дне календаря.
- Выбирайте нескольких участников, формат, дату, время Бангкока, длительность, проект, локацию и статус.
- Нажимайте карточку для редактирования. Для переноса измените дату или перетащите карточку.
- Фильтруйте по участнику, проекту, статусу и тексту. Новые проекты и локации вводятся прямо в форме. Кнопки «Добавить проект» и «Добавить локацию» позволяют указать несколько значений в одной съёмке; крестик удаляет отдельное значение. Фильтр проектов работает по каждому из них.
- Блок «Ближайшие съёмки» показывает до трёх ближайших или идущих сейчас съёмок с датой, временем, темой, участниками и локациями. Учитывает фильтры и все месяцы; нажатие открывает запись и нужный месяц. Отменённые и уже отснятые записи сюда не входят.
- «Обновить» загружает актуальные записи с сервера. Одновременные изменения одной записи защищены проверкой версии.
- «Скачать резервную копию» сохраняет JSON всех загруженных съёмок.

Календарь начинается пустым: вымышленные съёмки не добавляются. Участники — роли в календаре, а не отдельные учётные записи. Для доступа коллег нужно отдельно настроить доступ Sites.

## Секреты интеграций

Задаются только в хранилище секретов хостинга, не в репозитории и не в браузере:
- `HF_API_KEY_ID`, `HF_API_KEY_SECRET`: ключ Higgsfield (cloud.higgsfield.ai).
- `IG_APP_ID`, `IG_APP_SECRET`: приложение Meta с продуктом Instagram API with Instagram Login; redirect URI `https://<сайт>/api/integrations/instagram/callback`.
- `TOKEN_ENCRYPTION_KEY`: 32 случайных байта в base64 (`openssl rand -base64 32`) для шифрования токена Instagram.
- `FILE_LINK_SECRET` (необязательно): любая длинная случайная строка. Нужна только чтобы отдать Higgsfield загруженный в хранилище кадр для image-to-video по подписанной ссылке на 1 час.

Без них разделы работают в ручном режиме. Статус «Подключено» показывается только при наличии ключей на сервере.

Порядок настройки Instagram: 1) в developers.facebook.com создать приложение типа Business и добавить продукт «Instagram API with Instagram Login»; 2) указать redirect URI выше; 3) аккаунт Instagram должен быть профессиональным (Business или Creator) и добавлен тестировщиком, пока приложение не прошло проверку Meta; 4) задать три секрета и опубликовать сайт; 5) Настройки → Интеграции → «Подключить Instagram». Публикация ролика отмечается только после подтверждения сопоставления.

Higgsfield: ключ создаётся в cloud.higgsfield.ai (API keys), затем секреты `HF_API_KEY_ID` и `HF_API_KEY_SECRET` и лимит запусков в студии (по умолчанию 0, то есть запуски выключены). Каждый запуск платный по тарифу аккаунта и требует подтверждения.

Автосинхронизация Instagram: планировщика задач (cron) у проекта Sites нет, `hosting.json` поддерживает только `d1` и `r2`. Поэтому синхронизация выполняется, когда администратор открывает Настройки, не чаще раза в 6 часов; после ошибки повторяется только вручную.

## Внешний вид

Стиль в духе Notion: системный шрифт, нейтральная палитра, иконки lucide-react, тонкие линии и подсветка строк. Слои стилей: app/globals.css (календарь съёмок), app/platform.css (оболочка), app/notion.css (общий слой поверх). Названия этапов: «Сценарий», «Снято», «На монтаже», «Нужно согласовать», «Правки», «Согласовано», «Выложено». Higgsfield AI в редизайне не менялся.

## Роли и доступ (миграция 0005)

Владелец (адрес в `app/permissions.ts`) всегда имеет полный доступ, его нельзя понизить или отключить. Остальные получают роль только через запись в Настройки → «Команда и доступ», которая включена («Выдать доступ») и чья почта совпадает с почтой входа Sites:
- Администратор / контент-менеджер: всё редактирование, команда, интеграции.
- Руководитель (согласование): видит внутренние данные, комментирует, «Согласовать» и «На доработку» только для роликов в статусе «Ждёт обратной связи».
- Наблюдатель: только чтение внутренних данных.
- Выплаты: отдельная галочка. Наблюдатель с ней только видит выплаты; записывать могут администратор или руководитель с галочкой. Полный экспорт и восстановление: администратор с выплатами (владелец).

Запись можно подготовить без почты («адрес не подтверждён»): она ничего не открывает. Смена почты приостанавливает доступ до повторной выдачи. Назначение ответственным в задаче или ролике доступа не даёт. Настройки доступа самого Sites не меняются: если сайт закрыт, человека нужно отдельно пустить в Sites. Посетители без роли видят только общий план: без заметок съёмок, названий проектов, сценариев, локаций, ссылок на монтаж, задач, AI, выплат.

Восстановление из копии возвращает записи команды выключенными (статус «подготовлено»).

## Календарь: неделя

Вид «Неделя» (с понедельника) рядом с «Месяц» и «Список»: даты Бангкока, переход по неделям, «Сегодня», те же фильтры (участник, проект, статус, формат, поиск), время начала и окончания, открытие карточки, перенос перетаскиванием, «＋» в дне. Статус съёмки «Перенесено» означает, что новая дата ещё не выбрана; в подписке календаря такое событие отмечается отменённым.

## Файлы AI (R2)

`hosting.json` содержит `"r2": "BUCKET"`. Файлы хранятся закрыто и открываются только через `/api/ai/files` после проверки прав (участник команды). Загрузка: JPEG, PNG, WebP до 20 МБ, MP4, MOV, WebM до 95 МБ; тип проверяется по содержимому файла. Результаты Higgsfield копируются в хранилище сразу после готовности, любую ссылку можно сохранить кнопкой «Сохранить в хранилище». Скачивание по ссылке защищено от SSRF: только https и порт 443, без IP-адресов и внутренних имён, каждое перенаправление проверяется, размер ограничен. Без привязки хранилища показывается «Не подключено», ручной процесс со ссылками работает.

## Уведомления

Колокольчик в меню: просроченные и ближайшие задачи, ролики на согласовании (руководителю), правки и прошедшие даты публикации (редактору), съёмки сегодня и завтра, результаты и ошибки AI, истекающие ссылки провайдера, срок токена Instagram (администратору). Считаются из текущих данных, отметки «прочитано» у каждого свои. Писем, push и разрешений браузера нет.

Проверка: `node scripts/test-v28.mjs` (роли, неделя, проверки файлов и SSRF, уведомления, автоплан на границе месяцев, восстановление, контракты адаптеров Higgsfield и Instagram с подменённым fetch). `test-content-api.mjs` дополнен ролями, файлами и уведомлениями.

## Данные: задачи

Миграция `drizzle/0004_platform_tasks.sql` только добавляет таблицу `tasks`; откат `db/rollback/0004_platform_tasks.down.sql`. Создание идемпотентно по id, правка, архив и восстановление проверяют revision (409 при конфликте); каждое изменение пишется одной D1 batch вместе с audit. Задачи входят в полный экспорт и восстанавливаются только добавлением. Проверка: `node scripts/test-tasks.mjs`.

## Хостинг на своём Cloudflare

Кроме ChatGPT Sites сайт можно держать на бесплатном аккаунте Cloudflare (Workers + D1, без R2: оно требует карту, поэтому файлы AI там отключены и видна надпись «Хранилище не подключено»).

- Вход: `AUTH_MODE=password`. Заголовки `oai-authenticated-*` там не читаются вообще, личность берётся только из подписанной куки `gh_session` (lib/session.ts, 30 дней, HttpOnly, Secure). Страница `/login`, выход кнопкой внизу меню. Пока это вход только владельца.
- Секреты: `SESSION_SECRET` (создаёт скрипт выкладки, не короче 32 символов) и `OWNER_PASSWORD` (владелец задаёт сам, не короче 12). Без них вход выключен.
- Выкладка с Mac: `npm run build`, `npx wrangler login`, затем `node scripts/cf-deploy.mjs` (база «gost-home», новые миграции, выкладка, SESSION_SECRET). Проверка без изменений: `node scripts/cf-deploy.mjs --check`. Пароль: `npx wrangler secret put OWNER_PASSWORD --config dist/server/wrangler.cloudflare.json`.
- Данные переносятся полной копией: Настройки → «Скачать полную копию (JSON)» на старом сайте, затем «Восстановить» на новом (только добавляет недостающие строки).
- Тест: `node scripts/test-session.mjs`.
- Пароль владельца задаётся на сайте: `node scripts/cf-deploy.mjs --setup-link` открывает одноразовую страницу (8+ символов, буквы и цифры). Хранится хэшем в D1 (миграция 0006), после 10 неверных попыток вход блокируется на 15 минут.

## Разработка

Node.js >=22.13.0. Установить зависимости: `npm run install:ci`. Миграции: `npm run db:generate`. Сборка: `npm run build`. Локальный запуск: `npm run dev`. Локальную D1 базу нужно подготовить миграцией через Wrangler; облачные миграции выполняет Sites при публикации. Конфигурация проекта: `.openai/hosting.json`.

## Поделиться отдельной съёмкой

Откройте сохранённую съёмку и нажмите «Поделиться событием»: скопируйте ссылку или используйте системное меню отправки. По адресу `/events/<id>` открываются актуальные детали, без входа в аккаунт. Единственная кнопка «ДОБАВИТЬ В КАЛЕНДАРЬ» открывает отдельное событие `/events/<id>/calendar.ics`. На iPhone/iPad сервер готовит прямую ссылку `x-safari-https` на это событие, чтобы передать его из встроенного браузера в Safari. На остальных устройствах остаётся обычная HTTPS-ссылка. Переход передаёт одно событие, не подписку; он не требует Google Календаря. Некоторые приложения могут блокировать открытие Safari — обработку и добавление необходимо проверять на реальном iPhone. Это разовый импорт с напоминанием за 24 часа, а не новая подписка на календарь. Получатель подтверждает добавление на устройстве; способ открытия файла зависит от браузера и календаря. Для отменённых или начавшихся съёмок добавление недоступно, для удалённых — страница не найдена. Добавленная копия не получает дальнейшие изменения; актуальные дата и время всегда доступны по исходной ссылке.

Ранее опубликованная лента `/events/<id>/subscription.ics` сохранена для совместимости с уже добавленными подписками. Кнопок и ссылок подписки на странице приглашения больше нет.

В событии для календаря названия локаций и ссылка приглашения передаются в описании. Отдельные поля LOCATION и URL не заполняются, чтобы Apple Календарь не создавал блок «Геопозиция». Локации на сайте и странице приглашения сохраняются как прежде.

## Отмена и перенос

Выбор статуса «Отменено» предлагает три ближайших свободных дня для тех же участников и времени. Нажатие на вариант сразу сохраняет перенос существующей записи со статусом «Запланировано» и открывает нужный месяц. Можно также выбрать другую дату вручную; при пересечении с другими съёмками появится предупреждение. Кнопка «Отменить без переноса» сохраняет обычную отмену.

## Заметки и подготовка актёров

В форме есть два независимых поля: «Подготовка актёров» — что участникам нужно подготовить, и «Заметки» — сценарий и прочие детали. На странице приглашения и в файле календаря они отображаются отдельно. Текст, ранее записанный в общее поле, остаётся в «Заметках»; новое поле подготовки изначально пустое.
